# ANA特典航空券プランナー

ANAマイルで取れる特典航空券の空席を seats.aero のデータから探す静的Webアプリ（HTML/CSS/JS、PWA対応）。seats.aero の API を中継するローカルサーバー `serve.py` 付き。

## 機能
画面は「探す」と「設定」の 2 つだけ。8flyer 流の旅程ビルダーや清書機能は外し、seats.aero の窓口に徹した構成。

**探す**
1. 出発地・目的地・帰着地・クラス・人数・出発日・帰国日を入れる（カレンダーは祝日と ANA シーズンつき）
2. 時期（ロー／レギュラー／ハイ）、ANA 便のみ／他社便を含む場合の必要マイル、ANA 直行便の有無を表示
3. 「空席を探す」で seats.aero から実データを取り、ANA 直行便 → スターアライアンス各社のハブ経由（日本→ハブ／ハブ→目的地／目的地→ハブ／ハブ→日本の 4 区間）を同じハブで 1.5〜72 時間（24h 超は★）でつなぐ。詳細は次節

**設定**: 上部タブまたはフッターから開きます。合言葉、または自分の seats.aero APIキーを入力し「保存して接続確認」を押してください。情報はこのブラウザの localStorage に保存され、検索時に固定の Cloudflare Worker へHTTPSヘッダーで送信されます。共用端末では利用後に「接続情報を削除」を押してください。

**友人への共有**: https://mimausr-hub.github.io/ana-award-planner/ を送ってください。設定の「サイトのURLをコピー」も使えます。合言葉は別途伝えてください。秘密情報付きURLの生成・取り込みは廃止しました。公開サイトでは中継先を固定し、保存済みの任意の中継URLは使いません。

**表示の限界**: 必要マイルは1人分の往復参考値です（片道検索でも往復の参考値）。ANA便のチャート、シーズン、燃油は推定値を含みます。予約・発券前に公式サイトで確認してください。アシアナ航空は公式案内に合わせ、2026年12月17日以降の搭乗便をANA候補から除外します（出典: https://www.ana.co.jp/ja/jp/guide/amc/award/tk/zone/ ）。

## 空席つきルート探索（seats.aero Pro API）
「探す」の「空席を探す」。ANA 直行便（NH）を先に調べ、次に `data.js` の `liveCarriers`（VN/BR/SQ/TG/OZ/CA/LH/LX/OS/TK/AC/NZ）について
「日本→ハブ」「ハブ→目的地」「目的地→ハブ」「ハブ→日本」の 4 区間を seats.aero から全社まとめて取得し（ANA/JAL 直行便も同じ呼び出しに含める）、航空会社・ハブごとに振り分けて、同じハブで 1.5〜72 時間（24h 超は★）でつながる組合せを提示する。
便名・時刻・機材・残席つき。各便に seats.aero の該当日・該当区間を開くリンクが付く。往路と復路で別の航空会社を組み合わせることは可能（ベトナム航空を含む旅程は不可）。
- **会社をまたぐ乗継**: 同じアライアンス内なら、日本→地域の玄関ハブ（ANA 直行や提携長距離便）→現地の提携会社で目的地へ、という組合せも作る（`data.js` の `gatewaysByZone` が玄関ハブ、`starCodes`／`owCodes` が加盟会社）。日本便の無い現地会社（コパ＝パナマ、アビアンカ＝ボゴタ、エチオピア＝アディスアベバ、エジプト航空＝カイロ、ブリュッセル・TAP・LOT・エーゲなど。`jp: []`）のハブを挟む 3 区間（海外乗継 2 回・ストップオーバー 1 回まで）にも対応。そのため「玄関→現地ハブ」の区間を往復 1 回ずつ余分に取得する（API 計 6 回＋ページ送り）。行名は「ANA → コパ航空」のように矢印でつなぎ、総距離の短い現実的な経路を先に出す
- **ANA 提携特典のルールで絞る**（公式「ご利用条件」2025年6月24日以降の発券分）: 乗換地点が目的地より必要マイルの高いゾーンになる組合せを除外（例: 欧州行きのドーハ経由）、片道旅程では途中降機（24h 超）の組合せを除外、往復で往路・復路とも★しか無い会社には注意書き。海外乗換は往路・復路各 2 回までなので 3 区間までしか作らない。スターアライアンス各社と ANA は自由に組み合わせ可、クラス混在可
- 乗継候補の下に「ANA の複数都市画面に入れる区間」（① 東京(NRT) → サンフランシスコ(SFO) 4/15 …）を表示。ANA サイトは入力した区間しか検索しないので、ハブ経由の旅程はこの順で 1 便ずつ区間に入れる
- 表と候補の並びは、往路に候補がある会社を最優先（予約は往路から取るため）→ 復路もある → 燃油節約・取れそう度の順
- **人数**で絞る: 人数分の残席がない便は候補から外し、「人数未満 n 便を除外」とログ・要約に出す（残席 0 は席数不明として通す）
- **要約 1 行**: 往路・復路ごとに「○○経由で組める」「日本⇄ハブの長距離区間に空きなし（ハブ⇄目的地側は空いている）」のように、どこで詰まっているかをルールで判定して表示
- **表の数字**: 往路・復路の「○ 3日」は候補のある出発日の数
- **ビジネスが無ければエコノミーも探す**（既定 ON）: 往路か復路でビジネスの候補がゼロのとき、その側だけエコノミーで再探索
- **参考: ワンワールド系も見る**（既定 OFF）: JAL 直行、カタール（ドーハ）・フィンエアー（ヘルシンキ）・キャセイ（香港）・BA・マレーシア・カンタス・アメリカン経由を `liveCarriersOW` と `seatsSources.ow` で探す。ANA マイルでは予約できないので参考表示
- **燃油列**: ANA 便は `anaFuel`（ANA 公式の燃油特別付加運賃・1区間・円、2026年9〜10月発券分。設定タブの JSON で更新）×区間数、他社便は `carriers.fuel` の有無と `fuelRef` の実例ベースの目安
- **ワンワールド表の JAL マイル**: `data.js` の `jalChart`（JAL 公式 2026年4月16日更新）。JAL 便は路線別の基本マイル（片道×区間数。PLUS だと増える）、提携各社は seats.aero の区間距離を合計した総旅程距離から JMB 提携航空会社特典（1 社）の距離制チャートで算出し、2 社以上を組み合わせた場合のワンワールド特典の値も併記
- 希望日の前後日数は検索ボタンの横で変更できる。seats.aero は日付範囲を 1 回の呼び出しで返すので、広げても API 回数は変わらない
- **取れそう度モード**（チェックボックス）: 組合せを作る前に 3 日以上前のデータの便と会員枠のみ（ANA/JAL 不可の可能性大）の便を除外し（除外数をログに出す。要約の診断もその前提）、残った便について最終確認の新しさ（2h/12h/24h/72h で段階）・ANA/JAL 可の見込み（提携枠 +3、要確認 +1、会員枠のみ −3）・残席の余裕（人数+2 以上で +1）・複数プログラム掲載（+1）を点数化し、旅程はいちばん弱い便の点数×10＋合計で評価して高い順に並べる。各候補に「取れそう度 ◎／○／△」と理由を表示。◎＝全便が提携枠かつ 24h 以内に確認、△＝会員枠のみの便か 3 日以上前のデータ。燃油節約モードと同時 ON なら燃油優先の中で取れそう順
- **燃油節約モード**（チェックボックス）: 各候補の燃油サーチャージを便単位で見積もり（ANA 便・UA の日本発着区間は `anaFuel` の公式表、SQ/VN/NZ/AV/ET/CM/AA/QR/AS は 0 円、その他は日本発着なら公式表×会社係数、日本に関係ない区間は長距離 25,000・短距離 8,000×係数。`FUEL_FACTOR` と `FUEL_NONE`）、安い順に候補と行を並べ替え、表に「最安候補: 往路 約¥…／復路 約¥…」、各候補に「燃油目安」を表示する
- **片側だけの再検索**: 往路・復路の取得は別の呼び出しなので、片側の日付だけ変えて再検索したときは、条件（日付・前後日数・クラス・空港・プログラム）が同じ側の前回結果を 6 時間まで再利用し、変わった側だけ取り直す（API は半分程度）。「全部取り直す」ボタンでキャッシュを捨てられる。再読み込みするとキャッシュは消える
- **API 回数**: 全社・全クラス・全プログラムを 1 回の呼び出しにまとめるので、1 探索で往復 4 区間＋現地ハブ用 2 区間（片道 3 区間）。1 区間の結果が 1,000 件を超えると `skip` でページ送りするので実際は 6〜12 回程度（API の `cursor` は実測でページが進まないため使わない）。上限は 1 日 1,000 回（UTC 0 時＝日本時間 朝 9 時リセット）で、seats.aero に接続した他のアプリ（Claude の MCP など）と同じ枠を共有する。検索ボタンの横に本日この端末から使った回数を表示し（seats.aero が残回数ヘッダーを返す場合はそれを優先）、上限に達すると HTTP 429 `user_rate_limit_exceeded` が返るので画面にその旨を表示して途中までの結果を残す

## 必要マイルの出典
`data.js` の `partnerChart` は ANA 公式「提携航空会社特典航空券 ゾーン・必要マイルチャート」の **日本（Zone 1-B）発着・改定後**（2024年4月18日以降の発券分）の値。Zone 1-B は海外で乗り継ぐ旅程で、このサイトのハブ経由ルートはすべて該当する。国際線往復 2 区間だけ（提携社の直行往復）の旅程は Zone 1-A で少し安い（例: 欧州ビジネス 115,000、北米 110,000）。ゾーン 9（中南米）は Y 115,000 / C 195,000 / F 327,000、ゾーン 8（中東・アフリカ）は Y 100,000 / C 185,000 / F 290,000。中南米は ANA 便が無いので、ユナイテッド（ヒューストン・ニューアーク等）、エアカナダ（トロント）、ルフトハンザ・スイス・ターキッシュ（欧州）のハブ経由を探す。`anaChart`（ANA 便のみ）は動画の実演値と推定値のまま。

## 公開（GitHub Pages）＋ 中継サーバー
seats.aero の API はブラウザからの直接呼び出し（CORS）を許可していないので、GitHub Pages だけでは検索が動かない。`worker/` の Cloudflare Worker（無料枠）を中継にすると、ローカルの serve.py 無しで常時使える。手順は [worker/README.md](worker/README.md)。デプロイ済みの中継 URL は `https://ana-award-proxy.anamile.workers.dev`。サイトの設定タブに中継 URL と合言葉を入れる（この端末のブラウザにだけ保存される）。


```bash
cd ~/Downloads/ana-award-planner
git init && git add . && git commit -m "ANA特典航空券プランナー 初版"
gh repo create ana-award-planner --public --source=. --push
gh api -X POST repos/{owner}/ana-award-planner/pages -f build_type=legacy -f 'source[branch]=main' -f 'source[path]=/'
```
公開URLは `https://<ユーザー名>.github.io/ana-award-planner/`。

## seats.aero API について
空席探索は seats.aero の Partner API を使う。
- seats.aero Pro（月 9.99 ドル）に API が付属。設定 → API タブでキーを発行。1 日 1,000 回まで
- Pro のキーは**非商用利用**が条件。商用利用（買い手向けサービスに組み込む等）は seats.aero との書面合意が必要
- キーはブラウザに入れず、サーバーに渡すのが推奨:
  ```bash
  SEATS_AERO_KEY=xxxxxxxx python3 serve.py
  ```
  または同じフォルダに `.seats_aero_key`（1 行）を置く（.gitignore 済）
- 画面だけ試す: `SEATS_AERO_MOCK=1 python3 serve.py`（ダミー応答。実 API と同じ形で便・残席・区間距離を返すので、API を消費せずに画面を確認できる）
- 対象はスターアライアンス便の空席（united / aeroplan / lifemiles の在庫）。ANA 会員だけに開放される ANA 便の枠は含まれない。ベトナム航空は flyingblue / delta の在庫で代替
- 各便にどのマイレージプログラムの在庫に出ているか（UA/AC/AV/AS/AA/JAL など）のバッジを付ける。スターアライアンス表では ANA マイルで取れる見込みを併記: 運航会社以外の提携プログラム（UA/AC/AV）にも出ていれば「ANA可の見込み（提携枠）」、運航会社自身のプログラムだけ（エアカナダ便が Aeroplan のみ等）なら「自社会員枠のみ・ANA不可の可能性大」。ワンワールド表では JAL マイルで取れる見込みを併記: seats.aero の `jal` 在庫は JAL 運航便約 120 区間を追跡対象にしているが実データは空（2026-10 時点で 0 件。JAL PLUS で常時「空席あり」になるためと思われる）なので、JAL 運航便は「JAL便・JALサイトで要確認（PLUS なら取れる見込み）」、提携各社の便は他プログラムの出方から「JAL要確認（AA/BA/QF/CX/AY/QR Avios など共通枠の可能性）」「AS/自社のみ・JAL不可の可能性大（アラスカと運航会社自身の会員枠にしか出ていない。カタール航空に多い）」と推定表示。運航会社自身のプログラム（QR 便の Qatar Avios 等）は提携枠の根拠に数えない
- 各便に「最終確認」（seats.aero がその空席を最後に確認してからの経過。3 日以上は赤で「要確認」）を表示し、同条件なら新しいデータを優先して並べる
- ベトナム航空はスターアライアンス外で、seats.aero に出るのは Flying Blue／デルタ等に開放された枠。ANA に開放される枠とは別なので「参考」「ANAの枠とは別・要確認」と明示
- 候補の便は表（日付・便名・出発・到着・残席・機材・在庫・最終確認・seats.aero リンク）で表示。乗継候補は 2 行＋乗継時間の行。スマホ幅では機材と最終確認の列を隠す
- 便の発着は「都市（空港名 コード）」で表示（`data.js` の `airportNames`）。同じ都市で空港が変わる乗継（例: マルペンサ→リナーテ）はその旨を表示
- GitHub Pages 上では `worker/` の Cloudflare Worker を中継にする（seats.aero はブラウザからの直接呼び出しを CORS で拒否するため、設定タブの API キーだけでは動かない）

## 注意
- 数値は動画で実演された値（`src: "video"`）と推定値（`src: "est"`）。予約前にANA公式のマイルチャート・ルールを確認する。
- ANAのサイトへは自動アクセスしない（規約・ボット検知の問題を避ける）。空席は seats.aero で確認し、予約は ANA 公式サイトで行う。
- ベトナム航空はスターアライアンスではないため flyingblue / delta などの在庫で代替している。
